# 多软件授权管理平台需求规格说明书 V1.3

- 文档编号：AUTH-PRD
- 版本：V1.3
- 状态：需求基线（部分事项仍待确认）
- 范围：产品需求与约束，不代表功能已经开发或验收

## 1. 产品目标

建设一个面向多个独立软件产品的授权管理平台，提供软件身份管理、授权签发与验证、设备绑定、代理体系、授权额度、余额与支付、API 接入、安全审计、全球区域化部署及开发者文档能力。

## 2. 已确认技术基线

| 层级 | 已确认要求 |
|---|---|
| 后端 | ThinkPHP |
| 前端 | React + TypeScript |
| UI | shadcn/ui；前端 UI 必须使用该组件体系，不得自行仿制替代组件 |
| 数据库 | MySQL |
| 缓存 | Redis 集群/多级缓存 |
| 异步任务 | 消息队列 |
| 签名算法 | RSA-3072 + SHA-256 |
| 客户端范围 | 多种客户端，协议统一、SDK 可扩展 |
| 离线授权 | 每个软件可独立配置时长 |
| 密钥轮换 | 新旧密钥短期并行，迁移完成后撤销旧密钥 |
| 文档生成 | 自动生成基础文档 + 人工审核 |
| 代码审核 | 所有代码变更必须审核后才能合并 |

## 3. 用户与角色

已确认角色体系：管理员、代理、下级代理、用户。

### 3.1 管理员
管理全站软件、用户、代理、授权、额度、余额、支付、API 密钥、系统配置、密钥、日志与审计。

### 3.2 代理及下级代理
管理授权业务范围内的用户和授权。代理权限必须受数据范围约束。管理员统一设置代理购买价格；额度由管理员分配，代理不得自行向下级代理转额度。

### 3.3 用户
支持代理创建用户和用户自主注册两种方式。用户归属及转移规则仍有待确认。

## 4. 软件管理与软件身份

管理员创建软件时，系统自动生成软件身份及相关随机标识，不要求人工填写随机 ID。至少规划：
- App ID：公开的软件唯一标识。
- App Secret：敏感身份凭据，生成后按安全策略交付和轮换。
- Key ID：密钥版本标识。
- 软件授权命名空间及 API 身份标识。
- 软件签名密钥对及平台验证所需公钥配置。

标识必须使用密码学安全随机源或可靠的唯一标识方案。App ID 不是密码；不能把 App ID 当作认证凭据。私钥不能嵌入不可信客户端。

## 5. 授权业务

授权核心能力规划包括：
- 授权码单个/批量生成（批量能力仍需最终确认）。
- 软件、用户、代理、套餐及有效期关联。
- 激活、验证、查询、续费、换机、解绑、冻结、恢复、作废。
- 一机一码设备绑定；支持更换机器，已确认不限制换机次数。
- 月卡、季卡、年卡、永久卡等套餐由管理员维护。
- 授权状态、设备变更及操作历史可追溯。
- 授权凭证必须与软件身份、授权主体、设备策略和有效期关联。

续费是否再次消耗额度尚未确认。

## 6. 额度、余额与财务

- 额度按软件及套餐维度分别核算。
- 只有管理员可以分配额度；代理不能自行向下级代理转额度。
- 管理员统一设置代理购买价格。
- 代理余额可用于购买授权额度。
- 余额充值支持管理员手动充值和在线支付；支付渠道待确认。
- 需要余额流水、额度流水、购买订单、支付订单、退款及回调记录。
- 余额扣减、额度增加、授权开通必须具备事务、幂等和防重复处理。
- 授权开通失败不得错误扣除额度；财务流水必须完整审计。

## 7. API 与身份认证

规划 API 包括授权激活、验证、查询、换机、解绑、心跳，以及管理端授权创建/查询/续费/更换、用户及下级查询、额度查询等。

- 管理员 API 密钥可拥有全站授权范围。
- 代理 API 密钥只能操作其权限范围内资源。
- 软件身份凭据与管理员/代理 API 密钥分离。
- 支持权限控制、禁用、轮换、IP 白名单、请求签名、时间戳、Nonce、防重放、限流及调用审计。

## 8. 全球规模与日志

### 8.1 已确认目标
- 用户规模规划：100 万以上。
- 国内授权集群：独立扩展至 80,000 QPS。
- 海外授权集群：独立扩展至 80,000 QPS。
- 国内与海外规划流量比例：各 50%。
- 国内和海外分别部署独立授权集群。
- 两个区域均须以长期稳定承载目标 QPS 为设计目标。

以上为规划目标，不是已实现性能。必须通过真实部署、压测和持续运行测试验收。

### 8.2 日志策略
- 成功授权验证：保留统计数据。
- 异常授权验证：完整记录。
- 授权变更、设备变更、密钥操作、管理员操作及财务流水：完整审计。
- 成功请求统计至少包含区域、软件、请求量、成功/失败量、延迟分位数、缓存命中率及错误分布。
- 日志不得泄露私钥、App Secret、完整敏感凭据或不必要的个人信息。

## 9. 客户端与离线授权

支持多种客户端，采用统一协议和一致的错误码/状态定义。SDK 语言及平台范围按待确认事项逐步确定。

离线授权时长由管理员按软件独立配置。离线凭证须具备平台签名、软件及设备绑定、签发时间和过期时间；本地敏感缓存应加密。离线期间无法保证平台撤销状态即时抵达客户端，离线时长构成撤销生效延迟上限的重要因素。

## 10. 安全与防破解

采用多层防护：非对称签名、请求防重放、设备绑定、短期凭证、服务端状态校验、限流、异常检测、客户端完整性防护及安全审计。不得承诺客户端绝对不可破解；目标是提高攻击成本、降低凭据泄露影响并确保客户端无法伪造平台有效签名。

## 11. 开发治理与文档

- 所有代码变更必须通过 Pull Request / Merge Request 审核后合并。
- 所有代码变更记录文件路径、Diff、原因、关联需求/缺陷、作者、审核者、测试结果、Commit 和发布版本。
- 禁止未经记录的生产环境手工改码。
- 文档基础内容自动生成，并经人工审核后成为正式版本。
- 文档修改保留版本历史，代码、API、数据库、SDK、部署配置变更须检查对应文档是否同步。
- 审计记录应具备防篡改和备份机制。

## 12. 验收原则

每项需求必须有可验证的验收条件。性能目标需按区域单独压测，至少验证 80,000 QPS 长时间运行、P95/P99、错误率、资源水位、故障恢复及跨区域同步行为。具体延迟、可用性、RPO/RTO 和持续时间仍待确认。
## 13. 已完成确认的业务规则（V1.3）

### 13.1 代理与用户
- 代理售价统一由管理员设置；代理不得自行修改用户售价。
- 用户变更所属代理时，用户或管理员均可发起申请，最终由管理员审批。
- 自主注册且无代理归属的用户进入公共用户池，由管理员分配。
- 支持授权批量生成、批量导入和批量导出。

### 13.2 额度、续费与套餐
- 是否在续费时再次消耗额度，由管理员按软件独立配置。
- 永久授权表示不设置到期时间；管理员仍可冻结、恢复、作废及执行其他管理操作。
- 到期提醒在到期前 7 天、3 天、1 天触发。

### 13.3 全球区域与性能目标
- 国内、海外各自部署独立授权集群和独立数据库，区域内请求优先在本区域处理。
- 两区域通过消息队列同步经数据分类允许跨区域同步的数据；不得默认复制所有个人数据。
- 区域间网络中断时，已缓存且仍在有效租约内的授权可以继续验证；新授权和管理操作暂停，待恢复后补偿与对账。
- 冻结、作废、换机等重要变更跨区域传播目标为 1 秒以内；网络分区时无法保证该目标，必须告警、限制高风险操作并在恢复后补偿。
- 国内、海外各自持续承载 80,000 QPS 为规划和验收目标，不代表当前已实现。
- 性能验收基线：每区域连续 24 小时 80,000 QPS；区域内服务端 API P95 ≤ 50ms、P99 ≤ 100ms；可用性目标 99.99%。以上均须通过真实部署测试验证。

### 13.4 安全与 SDK
- 签名算法确定为 RSA-3072 + SHA-256，填充方案采用 RSA-PSS。
- 平台签名私钥由 KMS/HSM 托管，不可直接导出。
- 软件身份凭据支持平台生成管理，以及开发者自行生成并上传两种模式；平台签名私钥仍由平台控制。
- SDK 语言范围：C#、C++、C、Java、Kotlin、Go、Python、JavaScript、TypeScript、PHP、Rust、易语言；后续允许扩展。
- 每个软件可独立设置离线授权时长，范围 0～90 天；0 表示禁止离线验证。
- 密钥泄露响应支持紧急撤销、轮换、强制客户端升级、跨区域传播和审计。

### 13.5 财务与通知
- 结算支持多币种，由管理员配置启用币种及规则；金额必须按币种精度精确存储和计算，不得使用浮点数进行账务运算。不同币种不得直接相加；跨币种转换须有明确汇率、报价时点和审计记录。
- 充值支持管理员手动充值和在线支付。在线支付成功后自动入账；手动充值由管理员确认后入账。
- 授权额度购买订单不支持退款。重复扣款、重复支付、支付差错等仍须通过可审计的账务冲正/纠错流程处理，不得直接篡改流水。
- 支持站内通知、邮件、Telegram 机器人及可扩展通知渠道。
- 财务流水、安全审计日志永久归档；普通运行日志保留 180 天。归档须具备备份、访问控制和完整性保护。

## 14. 前端页面布局与视觉规范（强制）
- 前端必须使用 React + TypeScript 与 shadcn/ui；不得自行仿造或替换 shadcn/ui 组件体系。
- 每个页面必须有明确的信息层级和合理留白。页面标题、描述、工具栏、统计区、内容卡片、表格和分页之间必须有一致且可辨识的间距。
- 页面主内容区采用统一容器和间距规范；卡片内部必须设置合理 padding，表单字段之间保持统一垂直间距。
- 禁止标题、按钮、输入框、表格单元格或卡片内容紧贴边缘；禁止将所有内容堆叠在一起。
- 也禁止通过固定高度或过大的空白制造空旷页面。统计卡片使用响应式 Grid/Flex 布局，避免纵向无限拉伸。
- 桌面、平板和移动端均须响应式适配；窄屏下允许合理换行、折叠工具栏或横向滚动表格，不得造成内容重叠。
- 间距优先使用项目统一的 Tailwind spacing scale；组件优先使用 shadcn/ui，图标、按钮、表单、弹窗、菜单、表格等交互保持一致。
- 页面验收必须检查：对齐、间距、padding、响应式断点、空状态、加载状态、错误状态、长文本和密集数据场景。
