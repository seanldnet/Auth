# 安全与密钥管理规范（规划稿）

## 1. 已确认算法基线

数字签名算法：RSA-3072 + SHA-256。协议实现应采用经过审查的成熟密码学库和明确的签名编码规范。建议评估 RSA-PSS + SHA-256；最终填充参数、编码和跨语言兼容测试需在协议冻结前确认。不得自行设计密码算法。

## 2. 密钥用途隔离

至少区分：
- 平台授权签名密钥：平台签发授权凭证/配置。
- 软件服务端请求签名密钥：软件后端对请求签名。
- API 访问凭据：管理员/代理 API 身份与权限认证。
- 数据加密密钥：保护需要保密的数据。
- Key ID：标识密钥及其版本。

不同用途、不同软件、不同环境和不同区域的密钥应按风险隔离。不得把一个通用 Secret 同时用于所有签名、认证和加密用途。

## 3. 私钥保护

- 平台签名私钥应优先由 KMS/HSM 或等效受控密钥设施生成、保存和执行签名。
- 私钥不得写入前端代码、客户端安装包、普通日志、文档示例或 Git 仓库。
- 软件服务端私钥由软件服务端安全保管；客户端不能被视为可信私钥存储环境。
- 访问私钥应遵循最小权限、身份认证、操作审计和必要的双人审批。
- 备份、恢复、灾备和密钥销毁必须形成可审计流程。

## 4. 软件身份自动生成

创建软件时自动生成 App ID、Key ID 及所需凭据。App ID 是标识符而非密码；App Secret 是敏感凭据，须安全交付、限制读取并支持轮换。随机值必须来自密码学安全随机源。创建、查看、轮换、禁用、撤销均记录审计事件。

## 5. 密钥生命周期

状态建议：待启用、生效中、过渡中、已停用、已撤销、已过期。

正常轮换流程：
1. 创建新密钥及唯一 Key ID。
2. 发布/分发新公钥并确认区域同步。
3. 新签发内容使用新密钥。
4. 在受控过渡期内接受新旧密钥验证。
5. 统计旧 Key ID 的剩余使用量。
6. 迁移完成后撤销旧密钥并归档记录。

泄露响应必须支持紧急撤销，不受正常过渡期约束。撤销事件须传播至所有区域，并明确缓存失效和客户端更新机制。

## 6. 请求防护

授权 API 规划使用请求签名、时间戳、Nonce、防重放存储、请求体摘要、TLS、速率限制、权限校验和 IP 风险策略。Nonce 必须具备唯一性及有效期；签名规范必须明确规范化请求方法、路径、查询参数、请求体摘要和字符编码，避免不同 SDK 计算结果不一致。

## 7. 客户端防护边界

可采用代码混淆、完整性检查、调试检测、敏感缓存加密、短期凭证和服务端关键逻辑等措施。客户端运行在用户控制环境中，无法保证绝对不可破解；不得在客户端内置平台私钥或需要长期保密的服务端私钥。

## 8. 离线授权

每个软件独立配置离线时长。离线凭证应由平台签名，包含 App ID、授权标识、设备绑定摘要、签发时间、过期时间、凭证版本和 Key ID。客户端离线验签后仍须检查本地可信时间策略和凭证范围。

离线期间无法实时获知冻结/作废状态。管理员必须理解离线窗口越长，撤销状态最坏传播延迟越大。最大离线时长、时钟回拨防护和续租策略待确认。

## 9. 安全审计

完整记录异常验签、无效授权、设备不匹配、重放请求、密钥操作、权限拒绝、管理员操作及安全策略变更。不得记录私钥、App Secret 明文、完整认证头或不必要的个人信息。审计存储应具备访问隔离、完整性校验、备份和保留策略。
