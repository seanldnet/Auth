# 数据、缓存与日志设计（规划稿）

## 1. 数据域

规划数据域包括：
- 软件与软件密钥元数据。
- 用户、代理、下级代理及归属关系。
- 授权、套餐、设备绑定和授权状态历史。
- 软件/套餐维度额度账户及额度流水。
- 代理余额、余额流水、充值和支付订单。
- API 密钥、权限和调用记录。
- 安全事件、管理员审计和版本变更关联信息。
- 区域统计、性能指标和运行事件。

具体表结构、字段类型、索引、分库分表键和数据归属需另行形成数据库设计文档。

## 2. 额度与财务一致性

- 额度按软件和套餐维度独立核算。
- 余额和额度变动必须记录不可随意覆盖的流水。
- 扣款、加额度、创建授权应通过事务或可靠状态机协调。
- 支付回调必须验签、幂等处理和防重复入账。
- 失败补偿、退款和对账必须有明确状态及审计记录。
- 不得仅凭缓存余额决定最终资金结果。

## 3. 授权与设备一致性

激活和换机必须通过权威写入路径，使用唯一约束、事务和幂等保护。设备绑定历史应记录变更前后状态、操作主体、时间、原因和关联请求编号。设备指纹应采用最小化、不可逆或可控保护的摘要策略，避免无必要存储原始硬件信息。

## 4. 缓存

建议 L1 进程内缓存 + L2 区域 Redis + L3 权威数据库。缓存记录需包含版本、状态、有效期和密钥版本。对冻结、作废、换机等操作执行主动失效和版本检查。缓存不可替代权威数据，也不能无限期保存授权允许状态。

## 5. 区域数据

国内和海外分别部署独立授权集群。需要通过数据分类确定哪些数据留在本区域、哪些元数据允许跨区域同步、哪些数据不得跨境。跨区域事件需幂等、可重试、可对账，并监控最大传播延迟。具体主写区域、冲突解决和灾备切换规则待确认。

## 6. 日志策略（已确认）

- 成功授权验证：保留聚合统计，不要求每个成功请求都写完整业务日志。
- 异常验证：完整记录。
- 授权状态变更、设备变更、密钥管理、管理员操作、财务流水：完整审计。

异常记录建议字段：事件 ID、区域、App ID、Key ID（如适用）、授权 ID（如适用）、错误类别、时间、请求关联 ID、风险摘要、来源网络信息（按合规要求最小化）、处理结果。不得记录私钥、App Secret 或完整敏感认证数据。

## 7. 指标

至少采集各区域、各软件的 QPS、成功/失败数、P50/P95/P99 延迟、错误率、缓存命中率、数据库耗时、队列积压、节点资源、密钥同步状态及跨区域事件延迟。

## 8. 保留与归档

成功统计、异常日志、财务流水、密钥审计和管理员审计的保留期限尚未确认。应按数据类型设置差异化保留、归档、删除和法律保全规则。
## 9. 已确认的数据与财务规则

- 国内和海外分别使用独立数据库及区域写入服务，通过消息队列同步允许跨区域流转的数据；同步前执行数据分类与合规检查。
- 区域网络分区时，已缓存且仍在有效租约内的授权可继续验证；新授权和管理操作暂停。恢复后通过持久化事件、幂等消费和对账补偿。
- 重要授权变更跨区域同步目标为 1 秒以内；分区期间该目标不可保证，必须监控队列积压和最大传播延迟。
- 续费是否消耗额度按软件独立配置。
- 平台只按管理员配置启用 CNY 与 USDT 两种独立记账单位；CNY 展示 ¥，USDT 展示 U。余额、订单、价格、额度、流水必须分别核算，禁止汇率换算、自动兑换和跨币种抵扣。金额使用精确十进制或最小单位整数，禁止浮点数。
- 授权额度购买订单不支持退款。重复扣款、重复支付及其他资金差错必须使用独立冲正/纠错流水处理，不得删除或覆盖原始流水。
- 在线支付成功自动入账；管理员手动充值须经管理员确认后入账。
- 财务流水与安全审计日志永久归档；普通运行日志保留 180 天。永久归档须配套备份、访问控制、完整性校验和恢复演练。
- 支付回调必须验签、幂等、防重复入账，并校验金额、币种、商户订单号和订单状态。
## 10. CNY / USDT 双币种隔离

- CNY 与 USDT 是独立记账单位，不存在汇率换算、自动兑换或跨币种抵扣。
- 余额、价格、订单、支付流水均包含币种标识并分别核算。
- 金额使用对应币种/渠道约定的精确精度，禁止浮点数运算；币种精度配置须与支付渠道协议一致。
- 订单创建后固化币种和金额，支付渠道币种不匹配时拒绝下单。
